1. 런타임 아키텍처

하나의 배포 EXE가 명령행 mode에 따라 GUI, native service, CPU/memory worker, update helper 역할로 다시 실행된다. 별도 C++/Rust helper는 드라이버·입력·녹화 경계를 담당한다.

  • GUI/표현
  • Rust 조정·도메인
  • Worker/helper
  • 외부 시스템
  • 데이터·배포 원본
  • 실선 화살표: 명령/호출
  • 점선 화살표: event/저장/비동기 데이터

연결의 의미

  • GUI → service: window ID, channel, args를 JSON 요청으로 전송한다.
  • service → GUI: 응답과 상태 event, native window/tray 명령을 보낸다.
  • manager → worker/helper: validated 설정으로 시작하고 status/control 파일로 관리한다.
  • worker/helper → Windows: Win32·driver·파일 API를 실제로 호출한다.
  • service ↔ user data: 설정·원상복구 정보·helper 상태를 원자 JSON으로 저장한다.
  • updater → GitHub: 서명된 고정 자산만 받아 보호 cache로 이동한다.

2. 서명 업데이트와 rollback 흐름

설치형과 포터블은 manifest 이름과 교체 대상은 다르지만, 다운로드 전후 검증과 새 앱 health 확인 원칙은 같다.

핵심: 보안 검증 실패는 설치 전 중단이고, 교체 이후 health 실패는 백업 복원이다. 포터블 rollback 후 이전 EXE는 사용자가 결과를 확인하도록 자동 재실행하지 않는다.
