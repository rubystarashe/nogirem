1. 시스템 목적과 책임 경계

Nogirem은 Windows와 그래픽 드라이버의 공개 기능을 조정해 마비노기의 CPU 배치, 메모리 압력 대응, 네트워크 응답, GPU 설정, 선택형 입력·녹화를 관리한다. 게임 실행 파일·게임 메모리·통신 데이터를 직접 패치하는 구조는 아니다. 근거: README.md, OPERATION.md.

앱이 소유한다

UI·창·트레이, 설정 검증과 저장, helper 수명, Windows 설정 적용·복구, 업데이트 다운로드·검증·교체 orchestration.

앱 밖의 경계

Windows 프로세스·레지스트리·PowerShell, NVIDIA/AMD 드라이버, WebView2 Runtime, GitHub Releases, 게임·녹화 파일 시스템.

설치물의 실행 언어

GUI와 서비스는 Rust다. JavaScript는 보조 WebView 페이지와 preload에 남으며 Node.js는 개발·테스트·패키징 도구다. DIOXUS_MIGRATION.md

플랫폼

Windows 10/11 x64, WebView2, 관리자 권한을 전제로 한다. desktop/windows.manifest, desktop/Cargo.toml

3. 시작·종료 흐름

시작

  1. main.rs가 명령행 mode를 판별한다. updater/helper/service mode는 GUI를 열지 않고 해당 backend 함수로 분기한다.
  2. 일반 GUI 실행은 단일 인스턴스와 관리자 권한을 확인한다. 두 번째 실행은 기존 인스턴스에 focus request를 남긴다.
  3. Dioxus/WebView2 호스트가 main window와 native event loop를 준비한다. bridge::Client::start가 현재 EXE를 --native-service로 실행한다.
  4. service는 Environment, Windows, 도메인 manager, Updater를 구성하고 main window·tray를 요청한다.
  5. 초기 설정·상태 snapshot과 event가 GUI로 전달되고, 준비된 UI를 reveal한다. 3초 후 업데이트 확인, 이후 4시간 주기를 사용한다.

종료

닫기 요청은 service의 상태를 기준으로 즉시 종료 또는 확인 dialog로 이어진다. 적용된 boost가 있으면 복구·유지·취소를 선택하며, 녹화·update 같은 busy 상태는 종료를 제한할 수 있다. worker를 정상 정지한 뒤 service가 application.exit event를 보내고 GUI bridge는 renderer queue를 거치지 않고 native shutdown callback을 실행한다. 근거: bridge.rs, service.rs.

4. 요청·데이터·기능 흐름

UI 요청 공통 경로

Dioxus signal/event → Client::invoke(windowId, channel, args) → service request "invoke" → 계약·window kind 검사 → domain manager → response/event → UI state

보조 창은 창 종류별 preload와 허용 channel을 사용한다. service는 windowId로 창 종류를 찾아 채널 접근을 제한하며, 임의 URL이나 임의 창 종류를 열지 않는다. 근거: service-contract.json, service_windows.rs.

실시간 부스트

boost.rs가 affinity·memory worker를 시작하고 합성 상태를 보낸다. affinity worker는 약 5초 간격으로 프로세스를 분류하고 원래 mask를 기록하며, keep/reset 명령으로 종료 정책을 적용한다. affinity_worker.rs

메모리

memory.rs가 available/standby 임계값, rearm, 10분 cooldown을 적용한다. pressure 조건과 game 실행 여부를 만족할 때만 purge를 호출한다. config.json

네트워크

network_manager.rs가 상태 조회·적용·복구를 조정하고 network.rs/nic.rs가 Windows 설정을 다룬다. PowerShell은 compile-time asset으로 포함되며 timeout·출력 상한을 둔다.

그래픽·DXVK

graphics.rs는 NVIDIA/Radeon 상태와 적용을 조정하고 Radeon helper를 호출한다. dxvk_manager.rs는 호환성·설치·제거와 guide window 상태를 연결한다.

블랙박스

blackbox.rs가 recorder helper 수명·저장소·index·clip 작업을 관리한다. video_response는 Range를 지원하되 한 응답을 4 MiB로 제한한다. blackbox.rs

입력·터보 키

inputs.rs가 helper 설치·선택 키·간격·수명을 관리한다. 선택 helper는 공식 release URL과 해시/형식을 확인한 뒤에만 설치한다.

6. 권한과 신뢰 경계

  • UAC: 일반 GUI는 관리자 권한으로 다시 시작한다. 서비스와 자식 worker는 그 권한을 상속한다.
  • RPC: 외부 socket 대신 부모-자식 pipe를 사용한다. 그러나 JSON message 자체는 각 handler에서 schema·window kind·경로를 계속 검증해야 한다.
  • 경로: user input 경로는 canonicalization, 허용 root 포함 여부, 파일명/확장자, process path identity로 제한한다.
  • 다운로드: Ed25519 서명, semver, 고정 GitHub URL, 최대 크기, 정확한 size와 SHA-256을 검증한다.
  • 업데이트 캐시: reparse point 거부, High integrity label, directory handle 고정, final handle path 비교로 경로 치환을 방어한다.
  • helper: parent PID, duplicate lock, status/control files, 제한된 args로 lifecycle을 묶는다. 별도 프로세스지만 관리자 trust domain 밖의 sandbox는 아니다.
고위험 경계: 관리자 프로세스가 user-writable 경로, helper binary, PowerShell, driver API, update staging을 다룬다. 경로 검증이나 hash 검증을 단순화하는 변경은 파일 한두 개라도 security-sensitive로 취급해야 한다.

7. 설치형·포터블 업데이트

공통 검증

  1. update.json 또는 portable-update.json을 64 KiB 제한과 HTTPS로 받는다.
  2. embedded 공개키로 payload 서명을 검증하고 schema 1, release semver, 고정 자산 URL, 크기·SHA-256 형식을 확인한다.
  3. 새 파일을 create_new로 만들고 streaming hash·크기·취소를 검사한 뒤 sync_all한다.
  4. 설치 직전 파일을 다시 검증하고 보호된 job directory에 updater·payload·job metadata를 준비한다.

설치형

기존 앱에 정상 종료를 요청하고 설치 파일·설정 백업을 만든 뒤 NSIS 설치기를 실행한다. 새 nogirem.exe가 job nonce·version을 담은 healthy.json을 120초 안에 쓰면 완료로 간주한다. 실패하면 백업을 복원한다. desktop/installer.nsi, stop-installed-app.ps1.

포터블

배포물은 단일 launcher EXE이며 내부 앱을 관리자 전용 version cache에 푼다. marker는 버전이 아니라 package digest라 동일 버전 교체본도 재전개한다. 업데이트 helper는 원본 EXE와 같은 volume의 High-integrity staging에서 교체하고 열린 handle과 SHA-256으로 교체 후 실행 전 변경을 막는다. 실패하면 backup을 검증해 복원하지만 이전 EXE를 자동 실행하지 않는다. portable-distribution.md, desktop/portable.nsi.

10. 위험, 불일치, 변경 영향

변경 시 함께 봐야 하는 묶음

  • RPC channel: UI 호출, service-contract.json, service router, fixture/smoke를 함께 변경한다.
  • worker status: worker writer, ManagedProcess, service 상태 합성, UI event 소비를 함께 변경한다.
  • 설정 schema: 기본값, validation/normalization, 기존 JSON migration, 화면 form, 회귀 데이터를 함께 검토한다.
  • 업데이트: signer, manifest schema, client verifier, installer/portable NSIS, rollback QA를 하나의 보안 경계로 본다.
  • 보조 창: Rust window allowlist, preload channel, HTML/JS, media protocol, Escape/smoke matrix를 함께 본다.
정본 불일치 1: DIOXUS_MIGRATION.md 뒤쪽 “Rust backend migration in progress”는 역사적 중간 상태를 현재형으로 적고 있어, 같은 문서 앞부분과 현재 Rust service 코드에 모순된다.
정본 불일치 2: README.md 설치 절의 자산명 nogirem-setup-<version>.exe는 현재 verifier·packager가 요구하는 nogirem-dioxus-setup-<version>.exe와 다르다.
추정: 레거시 비교용 Node 테스트 다수가 남아 있어 테스트 수만 보면 현재 Rust 경로 검증량을 과대평가할 수 있다. 각 테스트가 어떤 실행 경로를 실제 호출하는지 구분해야 한다.
