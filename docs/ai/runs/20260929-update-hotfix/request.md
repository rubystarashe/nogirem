# 업데이트 전환 핫픽스 요구사항

- run_id: `20260929-update-hotfix`
- goal: Rust 0.4.1 대체 산출물과 Electron 0.3.19 전환본으로 업데이트·제거 실패 경로 복구

## 요구사항

- REQ-HOTFIX-01: Electron 0.3.17 이하 사용자가 0.3.19 전환본을 업데이트로 확인할 수 있어야 한다.
- REQ-HOTFIX-02: 0.3.19는 Rust 전환 가능 상태·진행률·실패 원인을 기존 업데이트 UI에 표시하고 사용자가 재시도하거나 화면을 숨길 수 있어야 한다.
- REQ-HOTFIX-03: Rust 버전은 올리지 않고 수정된 0.4.1 설치형·포터블 산출물과 서명 매니페스트로 기존 릴리스를 대체해야 한다.
- REQ-HOTFIX-04: 설치·제거 시 정상 종료 요청이 고착되면 설치 폴더 내부 프로세스만 제한적으로 종료해 진행할 수 있어야 한다.
- REQ-HOTFIX-05: 앱 종료 중 진행 중인 Rust 업데이트 다운로드를 취소해야 한다.
- REQ-HOTFIX-06: Rust 업데이트 다운로드는 Tokio runtime 없이 동작하고, 실패 시 원인과 재시도 동작을 UI에 표시해야 한다.
- REQ-HOTFIX-07: 이미 실패 상태인 Electron 0.3.18과 Rust 0.4.0 사용자를 위한 수동 복구 설치본과 안내를 제공해야 한다.
- REQ-HOTFIX-08: 동일 0.4.1 포터블 자산을 대체해도 변경된 내부 런타임을 다시 풀어야 한다.
- REQ-HOTFIX-09: 포터블 복구·롤백은 보호된 작업만 수락하고 사용자 쓰기 가능 경로의 교체 경쟁으로 임의 코드를 관리자 권한으로 실행하지 않아야 한다.
- REQ-HOTFIX-10: 완료·롤백·중단 작업 캐시를 복구 가능성을 보존하면서 제한적으로 정리해야 한다.
- REQ-HOTFIX-11: 설치·제거 종료 스크립트는 자신을 호출한 NSIS 프로세스를 앱 프로세스로 종료하지 않고, 형식이 다른 예약 작업 때문에 중단되지 않아야 한다.
- REQ-HOTFIX-12: WebView UI 전에 시작이 중단돼도 사용자별 bootstrap 로그로 마지막 시작 단계를 확인할 수 있어야 한다.

## 범위 제외

- Rust 0.4.2 버전 생성
- 사용자 설정·녹화 데이터 삭제
- 설치 폴더 밖 프로세스 강제 종료

## 수용 기준

- 0.3.17 이하 Electron 업데이터가 공개 릴리스에서 0.3.19를 선택한다.
- 0.3.19 전환 helper 상태가 UI 상태로 전달되고 오류 후 다시 실행할 수 있다.
- Rust 0.4.0 사용자 진단에서 확인된 다운로드 시작 패닉이 재현되지 않고 공개 서명 자산 다운로드가 완료된다.
- Rust·Node 테스트와 0.4.1 실서명 패키징, 0.3.19 bridge 패키징이 통과한다.
- 최종 v0.4.1 릴리스 자산의 해시·서명·라우팅을 공개 URL에서 검증한다.
- 0.3.18 사용자는 0.3.19, 0.4.0 사용자는 수정된 0.4.1 설치본의 직접 URL로 복구할 수 있다.
- 포터블 런타임 marker가 빌드 digest를 검증하고 동일 버전의 다른 빌드는 실행 중 캐시를 재사용하지 않는다.
- 포터블 교체 파일은 reparse를 거부하고 보호된 staging·열린 파일 handle·SHA-256 재검증을 거쳐 실행한다.
- 복구·롤백된 이전 포터블 EXE는 helper가 관리자 권한으로 자동 실행하거나 시작 프로그램에 자동 등록하지 않는다.
- 일반 업데이트 helper를 시작하기 전에 `result.json`을 포함한 신뢰 입력 전체를 보호 작업에 기록한다.
- 포터블 대상의 모든 상위 디렉터리는 reparse를 열지 않는 실제 handle로 위에서부터 고정하고 교체가 끝날 때까지 rename을 허용하지 않는다.
- 제거 스크립트에 NSIS 호출자 PID를 전달하고 예약 작업 action의 실행 파일이 없는 경우도 안전하게 건너뛴다.
